# #50 추가 QA 및 이후 단계 검토

작업 브랜치는 `fix/#50`이다. 아래 검토는 제공된 Figma의 디자인 컨텍스트와 스크린샷, 앱 소스, 회귀 검사, 연결된 Android 13 실기기 및 iOS 26.1 QA 시뮬레이터를 기준으로 했다.

## 추가 동작 수정

- 추가 사용자 지시에 따라 구글 로그인 버튼은 영어 화면에서만 표시한다(지원하지 않는 언어의 영어 화면 fallback 포함). 한국어 Android에서는 카카오만, 한국어 iOS에서는 카카오·Apple을 표시한다. 공통 로그인 버튼 목록도 동일하게 맞췄다.

- 스킨 선택 해제도 변경으로 인정해 저장 버튼을 활성화한다. 실제 서버에서 같은 인벤토리 ID의 장착 요청이 해제 토글로 동작함을 확인했다. 저장 전 현재 장착 ID를 조회하고, 이미 목표 상태라면 쓰기를 생략한다. 응답이 유실되어 재시도해도 다시 장착하지 않는다. 저장 후에도 목표 상태인지 확인한다.
- 실기기에서 멜빵바지 해제 저장 → 재진입 시 미선택·기본 캐릭터 → 재장착 저장을 확인했다. 최종 장착 상태는 테스트 전과 동일한 인벤토리 ID로 복원했다.
- 월별 캘린더의 ‘주별 보기’ 텍스트를 실제 닫기 버튼으로 연결했다. 실기기에서 월별 확장 → 주별 복귀를 확인했다.
- 온보딩과 닉네임 변경은 부모 KeyboardAvoidingView가 위치를 조절하고 공통 CTA가 키보드 표시 상태에 따라 모서리·좌우 여백을 전환한다. 키보드 위에는 폭 전체·모서리 0·하단 여백 0, 평상시에는 좌우 14·높이 48·반경 6을 사용한다. 단계 전환 시 키보드를 닫는다.

## 이후 단계·스킨 적용 범위

- 홈과 클로버 보상 시트는 서버의 `currentStage`, `currentStageMaxClover`, `totalCloverCount`를 우선 사용한다. 보상 목록도 단계순으로 정렬한다. 아직 안 받은 낮은 단계 보상 때문에 현재 단계가 잘못 계산되는 `lastReceivedOrUnlocked + 1` 처리는 제거했다.
- 서버 조회 전·실패 시의 단계 계산은 1~5단계 각 2개, 이후 각 14개, 최대 21단계의 공통 함수를 쓴다. 모든 단계 경계 및 서버 값 우선 사용을 검사했다. 21단계 목표를 넘으면 홈에 ‘최고 단계 달성’을 표시해 `1000/234` 같은 분모 초과 비율을 노출하지 않는다.
- 크기·본체 위치 보정이 확인된 착용 캐릭터는 로컬의 멜빵바지·공주·악마 3종이다. 세 자산의 1/2/3배 해상도 및 공통 캔버스 기준을 검사했다.
- 서버는 스킨 URL을 내려주지만, 확인한 4·6·21단계 URL은 의상만 그린 SVG다. 현재 장착된 1단계에서도 스킨 목록 `url`과 장착 조회 `skinUrl`은 같은 의상 SVG였다. 앱이 1~3단계의 착용 PNG를 별도로 사용해 온 이유다. 따라서 현재 응답·자산만으로 4~21단계의 완성 착용 모습·기본 캐릭터와 동일한 본체 크기까지 보장할 수 없다. 완성 캐릭터 이미지 또는 의상 합성 위치 규격이 필요하다. 서버 URL을 쓰는 아이콘과 보관함 미리보기는 SVG를 처리할 수 있는 기존 expo-image로 연결했다.
- 인벤토리 응답은 `inventoryItemId`, `isEquipped`, `acquiredAt`만 포함한다. 장착 ID로 확인한 스킨과 남은 항목이 하나뿐인 경우는 정확히 연결할 수 있다. 여러 항목을 획득 순서와 단계 순서만으로 짝지으면 잘못된 옷을 저장할 수 있으므로 추측 매핑을 제거했다. 연결이 불확실한 항목은 조회 실패로 처리하며 현재 확인된 스킨은 유지한다. 여러 보유 스킨 전체를 안정적으로 전환하려면 서버 응답에 식별 관계가 필요하다.

## 백엔드·디자인 담당자에게 전달할 메시지

스킨 후속 적용을 위해 두 가지 확인 부탁드립니다.

1. 인벤토리 각 항목에 `skinId` 또는 이에 대응하는 스킨 단계 정보를 함께 내려주실 수 있을까요? 현재 응답은 인벤토리 ID·장착 여부·획득 시각만 있어, 장착 중인 항목 외 여러 스킨을 정확히 연결할 수 없습니다. 획득 순서로 연결하는 추측 처리는 앱에서 제거했습니다.
2. 장착 조회의 `skinUrl`도 현재는 의상 아이콘 SVG입니다. 이후 단계에도 착용한 전체 로디 이미지를 내려주는 계약인지, 앱이 의상을 합성하는 계약인지 확인 부탁드립니다. 전체 이미지 방식이면 기본 캐릭터와 맞는 캔버스·본체 위치를 포함한 자산이 필요하고, 합성 방식이면 각 의상의 배치 좌표·크기 규격이 필요합니다.

이 문서는 전달 문안이며 외부 메시지 전송·이슈 등록·서버 변경은 하지 않았다.
