# #50 앱 수정 및 확인 내용

`origin/develop`의 `10f350e`를 기준으로 `fix/#50`에서 작업했다. 임시 APK 브랜치는 변경하지 않았다.

## 앱에서 수정한 항목

- 토스트: 홈의 1초 갱신마다 새로 생성되는 `onHide` 콜백이 표시 타이머를 초기화하던 문제를 수정했다. 현재 콜백은 ref로 읽고, 새 메시지·표시 상태·표시 시간에 대해서만 타이머를 시작한다. 이전 애니메이션과 종료된 화면의 콜백은 취소한다.
- 이어쓰기: 홈에 돌아오거나 선택 날짜가 바뀌면 임시저장 API를 별도로 조회한다. 캘린더 요청이 오래된 상태여도 저장 내용이 있으면 이어쓰기를 표시한다. 캘린더의 `HAS_DRAFT`·`INVALID_DRAFT` 상태도 유지하며, 이전 날짜의 늦은 조회 결과는 무시한다.
- 답장 보상: 서버는 `GET /reply` 과정에서 읽음 처리 후 `isRead=true`를 반환한다. 앱의 사전 조회가 첫 읽음 상태를 소비하던 흐름을 제거하고, 캘린더로 상태만 조회한 뒤 사용자가 답장을 열 때 본문을 요청한다. 조회 전 상태를 기준으로 첫 읽음 팝업을 표시하며, 중복 클릭·재열기에는 다시 표시하지 않는다. 클로버 요약 조회가 늦어도 편지 표시를 막지 않는다.
- 클로버 팝업: 제공된 [Figma 노드](https://www.figma.com/design/XQJJPghODs4vFiKTQJiVsM?node-id=5110-44546)의 212px 폭, 110px 이미지 영역, 간격·서체·버튼·40% 딤을 반영했다. Figma의 체크무늬 이미지 대신 사용자 선택에 따라 기존 클로버 아이콘을 사용했다. 미션 문구는 실제 클로버 수에 따른 단계·진행도로 표시한다.
- 스킨: 홈의 기본 캐릭터 고정 표시를 제거하고 화면 복귀 시 장착 정보를 조회한다. 보관함과 홈이 같은 의상 이미지 매핑을 사용한다. 미장착 응답의 nullable 필드도 DTO에 반영했다.
- 스킨 크기: 로컬 의상 PNG의 200×210 캔버스와 상단 40px 투명 여백을 보정해 기본 SVG의 118×167 본체와 같은 배율·발 위치로 표시한다. 128×183 홈 프레임과 단계 배지 위치는 유지하며 넓은 장식은 자르지 않는다. 크기를 알 수 없는 원격 이미지는 기존 전체 이미지 비율을 유지한다.
- 홈 단계 표시: 분모 `2` 고정을 제거하고 누적 목표를 사용한다. 2개는 `2단계 2/4`, 4개는 `3단계 4/6`, 10개는 `6단계 10/24`로 표시한다. 단계 경계 계산은 답장 보상 미션과 공통 모듈을 사용한다.

- 보관함 복원: 진입·복귀 시 장착 스킨을 함께 조회해 해당 인벤토리 ID와 의상으로 선택 카드·미리보기를 복원한다. 조회 실패를 빈 보관함으로 표시하지 않고 재시도를 제공하며, 확인된 기존 상태를 유지한다. 일부 응답 누락 시 임의 ID를 생성하지 않으며, 식별이 확인된 항목만 처리하고 조회·저장 진행 중에는 저장을 막는다. 실제 장착 상태는 목록 정렬이나 인벤토리의 장착 플래그보다 우선한다.

## 검증

- `npm run test:home`: React 기반 화면·수명주기, 이미지 프레임 및 단계 경계, 서비스 회귀 검사 61개.
- `npm run test:ads`: 광고 컨트롤러 회귀 검사 32개.
- `npm run test:notifications`: 기존 회귀 검사 49개.
- `npm run test:updates`: 기존 회귀 검사 33개.
- 전체 TypeScript 검사 및 변경 파일 ESLint.
- iOS 26.1 / iPhone 16e 개발 네이티브 빌드 성공.
- Android 배포용 JavaScript 번들 생성 성공.
- 별도로 만든 시뮬레이터와 모형 데이터로 임시저장 성공 후 토스트 종료·이어쓰기·내용 복원, 스킨 저장 후 홈 반영, 첫 답장 클로버 팝업·확인, 재열기 시 팝업 미표시를 확인했다. 임시저장 UI 검사는 미리 준비한 저장 내용을 다시 저장하는 흐름이며 새 저장에 따른 상태 변경은 회귀 검사에도 포함했다.
- 팝업과 홈의 실제 스크린샷을 Figma 기준 및 기존 의상 자산과 대조했다.
- 연결된 Android 13 실기기에 개발 빌드를 설치·실행하고, 추가 수정 후 홈의 의상 본체 크기와 실제 `2단계 2/4` 표시를 확인했다. 추가 수정은 JavaScript 변경이므로 개발 서버를 통해 반영했다. 보관함에서 실제 계정의 멜빵바지 선택 테두리와 착용 미리보기를 확인했고, 화면을 나갔다가 다시 진입해도 선택이 유지되었다. Android UI 계층에서도 멜빵바지 카드의 selected=true를 확인했다.

전용 시뮬레이터, 검증용 로그인 값·API 모형, 임시 진입 코드는 확인 후 제거했다. 실제 사용자 계정의 일기·회원정보를 변경하는 테스트는 하지 않았다. 추가 QA에서는 스킨 해제 저장과 재장착을 시험한 뒤 원래 장착 상태로 복원했다. Android 실기기의 임시저장·답장 보상 전체 흐름 재검증과 서버의 예약 시각 발송은 이 검증 범위에 포함하지 않는다.

## 백엔드 담당자에게 전달할 메시지

예약 알림과 답장 줄바꿈 확인 부탁드립니다.

1. **예약 알림:** Firebase 테스트 푸시는 정상 수신되지만 앱에서 선택한 시간에는 오지 않습니다. 서버 `stage` 코드에서 FCM 토큰만 갱신할 때 생략된 `time`이 `23:30`으로 바뀌는 것을 재현했습니다. 시간 생략 시 기존 값을 유지하도록 수정하고, 실제 배포 버전과 스케줄러 발송 로그도 확인 부탁드립니다. 답장이 없는 신규 사용자에게도 기본 언어로 발송되는지 함께 확인 부탁드립니다.
2. **답장 줄바꿈:** 앱은 답장 원문을 그대로 표시하며 일정 글자 수마다 개행하는 처리는 없습니다. 응답 `content`에 반복적인 개행이 들어가는지, 현재 프롬프트·예시·폴백의 영향을 받는지 확인 부탁드립니다. 원문에 개행이 없다면 비식별 재현 본문을 주시면 앱 렌더링을 이어서 확인하겠습니다.

서버 조사 기준은 `stage` 커밋 `8dadb8144c8de1ebadafbdaa27cd7a57dc656760`이며, 실제 배포 버전·응답 원문·운영 로그는 추가 확인이 필요하다. 서버 코드는 수정·커밋·배포하지 않았다. 예약 알림은 담당자의 서버 수정·배포 후 실제 예약 시각 수신을 재검증해야 한다.
